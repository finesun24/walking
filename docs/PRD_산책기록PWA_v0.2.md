# 1. 서비스 정의

## 1.1 한 줄 정의

산책하다 마음에 든 장면을 찍으면, AI가 그 순간의 맥락을 읽어 캡션·태그·무드를 붙이고, 지도에 핀으로 쌓이는 **개인 산책 기록장**.

## 1.2 문제

산책 중에 마음에 드는 장면을 찍는 사람은 많지만, 그 사진들은 갤러리에 흩어져 다시 열리지 않는다.

- 갤러리는 시간순으로만 쌓여서 "지난달 그 골목"을 찾기 어렵다
- 인스타그램에 올리려면 캡션을 고민해야 하고, 보여줄 만한 사진인지 스스로 검열하게 된다
- 지도 앱은 '가본 곳'은 저장해도 '그때 어땠는지'는 남기지 않는다

**기록의 마찰이 크고, 쌓여도 다시 보게 되지 않는다.**

## 1.3 해결 가설

| # | 가설 | 검증 지표 |
|---|---|---|
| H1 | 캡션 부담을 AI가 지면 기록 마찰이 줄어 더 자주 찍는다 | 주당 핀 등록 수 |
| H2 | 사진이 지도에 쌓이면 '내 동네 지도'라는 소유감이 생겨 다시 열어본다 | 등록 없이 열어보기만 한 세션 비율 |
| H3 | 남에게 안 보여주는 전제면 문턱이 낮아진다 | 첫 주 3개 이상 등록 비율 |

## 1.4 차별점

캡션을 **사진 이미지만으로 만들지 않는다.** 촬영 시각에서 뽑은 계절·시간대·요일, 그리고 사용자가 남긴 한 줄을 함께 넣는다.

> 사진만 → "골목길 풍경이 인상적이다" (어느 AI나 비슷)
> 맥락 포함 → "늦여름 해질녘 골목, 비 냄새가 남아 있다" (그 순간에만 나오는 문장)

## 1.5 경쟁 서비스

| 서비스 | 하는 것 | 안 하는 것 |
|---|---|---|
| 갤러리 앱 | 자동 저장, 지도 뷰 | 맥락 있는 문장 |
| 인스타그램 | 사진+캡션+공유 | 비공개 전제, 자동 캡션 |
| 지도 즐겨찾기 | 장소 저장 | 그 순간의 감상 |
| **이 서비스** | 사진 + 맥락 문장 + 지도 축적 | 소셜, 공유, 좋아요 |

# 2. 사용자

## 2.1 타겟

20~30대. 걷는 걸 좋아하고 산책 중 사진을 종종 찍는다. SNS에 올릴 만큼은 아니지만 지우기엔 아까운 사진이 갤러리에 쌓여 있다. 다이어리·필름카메라·일기 앱 경험자.

## 2.2 사용 맥락 — 디자인에 직접 영향

**기록할 때 (밖에서)**
- 한 손 조작. 걸음을 멈추고 오래 붙잡고 있을 수 없다
- 야외 직사광선 아래 화면을 본다
- 데이터 환경이 불안정할 수 있다
- → **촬영부터 저장까지 10초 이내**

**회고할 때 (집에서)**
- 침대나 소파. 시간 여유 있음
- 며칠~몇 달 뒤에 열어본다
- → 이때가 진짜 가치가 발생하는 순간. **회고 화면에 디자인 밀도를 더 준다**

## 2.3 비타겟

팔로워를 늘리려는 사람 / 러닝·등산 기록(거리·페이스)이 목적인 사람 / 맛집 리뷰를 남기려는 사람

# 3. 핵심 흐름

## 3.1 기록 루프 (밖에서, 10초)

```
장면 발견
 → 홈화면 아이콘 탭 (설치된 PWA)
 → [촬영] 버튼
 → 카메라 열림 + 동시에 위치 요청 (백그라운드)
 → 촬영
 → 한 줄 메모 (선택, 건너뛰기 가능)
 → 저장 → 피드/지도에 즉시 반영
 → [백그라운드] AI가 캡션·태그·무드 생성 후 카드에 채워짐
```

**원칙: AI 응답을 기다리게 하지 않는다.** 저장은 즉시 끝나고 캡션은 나중에 채워진다.

## 3.2 회고 루프 (집에서)

```
앱 열기
 → 피드: 날짜순 카드
 → 지도: 내 동네에 흩어진 핀
 → 대시보드: 태그 클라우드 / 요일별 그래프 / 무드 분포
 → 카드나 핀 탭 → 상세
```

# 5. 화면 명세

## 5.0 전체 구조

```
스플래시
  ├─ (최초) 온보딩 3장 → 로그인
  ├─ (미로그인) 로그인
  └─ (로그인됨) 홈

홈 — 하단 탭 3개 + 중앙 촬영 버튼
  ├─ 피드 (기본)
  ├─ 지도
  └─ 대시보드

촬영 플로우 (전체화면 모달)
  촬영 → 메모 입력 → 저장 → 피드 복귀

상세 (전체화면)
```

---

## 5.1 스플래시

| 항목 | 내용 |
|---|---|
| 노출 | 앱 부팅 시 항상 |
| 지속 | 최소 0.8초 ~ 세션 확인 완료까지 |
| 구성 | 서비스 로고/워드마크, 한 줄 태그라인 |
| 배경 | 브랜드 색 단색 또는 은은한 그라디언트 |
| 동작 | 이 사이에 Supabase 세션 확인 + 온보딩 완료 여부 확인 |

**디자인 노트:** 산책·걷기의 정서를 담되 과하지 않게. 로딩 스피너 없이 정적으로.

---

## 5.2 온보딩 (3장, 최초 1회)

가로 스와이프. 하단 인디케이터 3개. 우상단 "건너뛰기".

| # | 메시지 | 시각 |
|---|---|---|
| 1 | 마음에 든 장면, 그냥 찍어두세요 | 촬영 순간 일러스트 |
| 2 | 캡션은 AI가 씁니다 | 사진에 문장이 붙는 모습 |
| 3 | 걸을수록 내 지도가 채워져요 | 핀이 쌓인 지도 |

**마지막 장 하단:** "시작하기" 버튼 → 로그인

**설계 의도:** 3장이 각각 F4(촬영) / F7(AI) / F13(지도)에 대응한다. 서비스의 세 축을 그대로 보여주는 구조.

**주의:** 위치 권한을 여기서 요청하지 않는다. 첫 촬영 시점에 요청한다. 맥락 없이 물으면 거부율이 높다.

---

## 5.3 로그인 / 가입

| 항목 | 내용 |
|---|---|
| 구성 | 이메일 / 비밀번호 / [로그인] / "가입하기" 전환 텍스트 |
| 검증 | 이메일 형식, 비밀번호 6자 이상 |
| 에러 | 입력란 하단 인라인 표시. 토스트 아님 |
| 로딩 | 버튼 내부 스피너, 버튼 비활성화 |

---

## 5.4 홈 — 공통 셸

**하단 탭바 (고정)**

```
[  피드  ] [  ●촬영  ] [  지도  ] [ 대시보드 ]
```

- 중앙 촬영 버튼은 다른 탭보다 크고 시각적으로 튀게. 이 앱의 주 동작이다
- 탭바는 엄지 도달 범위 안 (화면 하단 고정)
- 상단 헤더는 화면별로 다름

---

## 5.5 피드

**카드 1개 구성**

```
┌─────────────────────────┐
│  [사진 — 4:3 또는 1:1]   │
│                         │
├─────────────────────────┤
│ ● 고요            8/26  │  ← 무드 점(색) + 무드명 + 날짜
│ 늦여름 해질녘 골목,      │  ← 캡션
│ 비 냄새가 남아 있다      │
│ #골목 #해질녘 #한적함    │  ← 태그
└─────────────────────────┘
```

- 정렬: `taken_at` 내림차순
- 날짜가 바뀌는 지점에 날짜 구분 헤더
- 무한 스크롤 (20개씩)

**상태별**

| 상태 | 화면 |
|---|---|
| 빈 상태 (0개) | 일러스트 + "첫 산책을 기록해보세요" + [촬영하기] 버튼. **가입 직후 반드시 보는 화면이므로 가장 공들일 것** |
| 캡션 생성 중 | 캡션 자리에 스켈레톤 바 2줄. 사진은 이미 보임 |
| 캡션 실패 | "캡션을 만들지 못했어요" + [다시 시도] |
| 로딩 | 카드 스켈레톤 3개 |

---

## 5.6 촬영 플로우 (전체화면 모달)

**Step 1 — 촬영 선택**

```
[ 카메라로 찍기 ]   ← 주 동작, 크게
[ 갤러리에서 고르기 ]  ← 보조
```

**Step 2 — 메모 입력**

```
[촬영한 사진 미리보기]

한 줄 남기기 (선택)
[ ________________ ]  최대 50자

📍 위치 확인됨 · 정확도 12m     ← 또는 "위치 찾는 중..." / "위치 없음"

[ 저장 ]      [ 건너뛰고 저장 ]
```

- 메모는 **반드시 건너뛸 수 있어야 한다.** 10초 룰의 핵심
- 위치 상태를 여기서 보여준다. 실패해도 저장은 가능

**Step 3 — 저장 직후**

즉시 피드로 복귀. 새 카드가 맨 위에 캡션 스켈레톤 상태로 나타남.

**위치 권한 요청 화면 (최초 촬영 시)**

권한 팝업 직전에 이유를 설명하는 화면을 먼저 띄운다.
"찍은 장소를 지도에 남기려면 위치가 필요해요"
[ 허용하기 ] [ 나중에 ]

**거부 시:** 위치 없이 저장 가능. 지도에는 안 뜨고 피드에만 남음.

## 5.8 지도

- 전체 화면 지도 (Leaflet + OpenStreetMap)
- 핀 색 = 무드 색
- 초기 뷰: 전체 핀이 들어오는 범위. 핀 0개면 현재 위치
- 핀 탭 → 하단에 미니 카드 슬라이드업 (썸네일+캡션) → 탭하면 상세
- 핀 밀집 시 클러스터링

**빈 상태:** 지도 위 반투명 오버레이 + "아직 핀이 없어요"

---

## 5.9 대시보드

**상단 요약**

```
총 32개 핀 · 12일 산책
```

**① 태그 워드 클라우드**
- 등장 빈도에 따라 글자 크기 차등 (최대/최소 3배 이내)
- 상위 20개까지
- 5개 미만이면 "태그가 더 모이면 보여드릴게요"

**② 요일별 기록 수 — 막대 그래프**
- x축 월~일 7개 고정
- 가장 높은 요일 강조 + "토요일에 가장 많이 걸었어요"

**③ 무드 분포 — 도넛 차트**
- 무드별 고유 색 사용
- 중앙에 최다 무드 표기
- 범례는 비율 순

**빈 상태:** 핀 3개 미만이면 "기록이 조금 더 쌓이면 보여드릴게요"

# 6. 디자인 방향

## 6.1 원칙

| # | 원칙 | 이유 |
|---|---|---|
| 1 | 사진이 주인공 | UI 요소가 사진을 이기면 안 됨 |
| 2 | 야외 가독성 | 직사광선 아래서도 읽혀야 함. 저대비 회색 텍스트 금지 |
| 3 | 엄지 도달 범위 | 주요 동작은 화면 하단 1/3 안에 |
| 4 | 큰 탭 타겟 | 최소 44×44pt. 걸으면서 누른다 |
| 5 | 기록은 빠르게, 회고는 느긋하게 | 촬영 흐름은 최소 요소 / 회고 화면은 밀도 있게 |

## 6.2 무드 색상 — 디자인 시스템의 축

무드 8종에 고유 색을 배정한다. 이 색이 **피드 카드 · 지도 핀 · 무드 차트**에서 일관되게 쓰인다.

| 무드 | 색 | 인상 |
|---|---|---|
| 고요 | `#7B8FA1` | 차분한 청회색 |
| 설렘 | `#F0836B` | 밝은 코랄 |
| 쓸쓸 | `#5B6785` | 흐린 남색 |
| 따뜻 | `#E2A044` | 앰버 |
| 활기 | `#E85D3A` | 선명한 주황 |
| 몽롱 | `#9B8AA6` | 연보라 |
| 청량 | `#5FB3B3` | 민트블루 |
| 아늑 | `#B98D63` | 흙빛 베이지 |

> 이 8종은 **DB CHECK 제약과 AI 응답 스키마 enum에 하드코딩되어 있다.** 값을 바꾸려면 SQL과 API 라우트를 함께 수정해야 한다.

## 6.3 기본 톤

- 배경은 밝게. 사진 색이 살아야 함
- 무채색 베이스 + 무드 색을 액센트로만
- 라운드: 카드 16px, 버튼 12px
- 타이포: 시스템 폰트. 캡션은 본문보다 한 단계 크게 (읽히는 게 목적)

# 7. AI 캡션 설계

## 7.1 입력

| 재료 | 예시 | 출처 |
|---|---|---|
| 이미지 | (base64) | 촬영 |
| 계절 | 늦여름 | `taken_at` 파생 |
| 시간대 | 해질녘 (19시경) | `taken_at` 파생 |
| 요일 | 수요일 | `taken_at` 파생 |
| 사용자 메모 | "비 냄새 좋다" | 사용자 입력 (선택) |

## 7.2 출력

```json
{
  "caption": "늦여름 해질녘 골목, 비 냄새가 남아 있다",
  "tags": ["골목", "해질녘", "한적함"],
  "mood": "고요"
}
```

## 7.3 품질 기준

**지킬 것**
- 1~2문장, 40자 내외
- 평서형(~다) 또는 명사형 종결. 존댓말 금지
- 계절·시간대를 문장에 녹임 (나열 아님)
- 사용자 메모가 있으면 그 감정을 최우선 반영

**금지**
- 사물 나열 ("나무와 벤치와 하늘이 보인다")
- 과한 미사여구 ("찬란한 황금빛 노을이 온 세상을")
- 조언·훈계 ("이런 순간을 놓치지 마세요")
- 이모지, 해시태그, 느낌표
- 얼굴 묘사, 신원 추측

## 7.4 태그 규칙

3~5개, 각 6자 이내 한국어 명사. 대상(골목·하늘·담벼락) + 상태/분위기(비온뒤·해질녘·한적함).

## 7.5 실패 처리

| 상황 | 처리 |
|---|---|
| 응답 지연 | 카드에 스켈레톤. 백그라운드 계속 |
| 생성 실패 | `caption_status = failed`, [다시 시도] 노출. 핀은 유지 |
| JSON 파싱 실패 | 502 반환, 재시도 |
| 안전필터 차단 | `finishReason` 함께 반환 |
| 무드가 8종 밖 | `null` 저장 (차트에서 제외) |

# 8. 데이터 모델

```sql
create table public.pins (
  id             uuid primary key default gen_random_uuid(),
  user_id        uuid not null references auth.users(id) on delete cascade,

  image_path     text not null,      -- {user_id}/{timestamp}.webp

  lat            double precision,
  lng            double precision,
  accuracy       double precision,   -- 미터. 100 초과면 실내 가능성

  taken_at       timestamptz not null default now(),
  user_note      text,

  caption        text,
  tags           text[] not null default '{}',
  mood           text,
  caption_status text not null default 'pending',

  created_at     timestamptz not null default now(),

  constraint pins_mood_check check (
    mood is null or mood in ('고요','설렘','쓸쓸','따뜻','활기','몽롱','청량','아늑')
  ),
  constraint pins_caption_status_check check (
    caption_status in ('pending','done','failed')
  )
);

create index pins_user_taken_idx on public.pins (user_id, taken_at desc);
create index pins_tags_idx on public.pins using gin (tags);
```

**RLS:** 4개 정책 모두 `auth.uid() = user_id`.

**Storage:** 버킷 `walk-photos` (비공개). 경로 첫 폴더 = `user_id`. 정책이 `(storage.foldername(name))[1] = auth.uid()::text` 로 검사하므로 **경로 규칙을 어기면 업로드가 403으로 막힌다.**

**집계 함수:** `tag_counts()` — 태그 배열을 펼쳐 사용자별 빈도 반환 (워드클라우드용).

# 9. 기술 구조

## 9.1 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js (App Router) | |
| 배포 | Vercel | API 라우트가 서버리스 함수로 동작 |
| DB/인증/스토리지 | Supabase | 외부 연동 ① |
| AI | Gemini Vision | 외부 연동 ② |
| 지도 | Leaflet + OpenStreetMap | API 키 불필요 |
| 차트 | Recharts | |

**모델:** `gemini-3.5-flash` 기본, `GEMINI_MODEL` 환경변수로 교체 가능.
`gemini-2.0-*`, `gemini-1.5-*` 는 **이미 종료되어 404를 반환한다.**

## 9.2 API 계약

```
POST /api/caption          (서버리스 함수, Node 런타임, maxDuration 30s)

Request
{
  imageBase64: string,     // data URL 접두사 제거된 값
  mimeType: "image/webp",
  takenAtLocal: string,    // 클라이언트 로컬 시각 ISO
  userNote?: string | null,
  lat?: number | null,
  lng?: number | null
}

Response 200
{ caption, tags[], mood, model }

Error
401  로그인 필요
500  GEMINI_API_KEY 미설정
502  Gemini 오류 / 파싱 실패
504  타임아웃
```

## 9.3 키 관리

| 변수 | 노출 | 위치 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 공개 | 클라이언트 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 공개 (RLS가 방어선) | 클라이언트 |
| `GEMINI_API_KEY` | **비공개** | 서버 전용 |
| `GEMINI_MODEL` | 비공개 | 서버 전용 |

- `.env.local` 은 Git에 커밋하지 않는다 (`git check-ignore -v .env.local` 로 확인)
- Vercel은 Settings > Environment Variables 에 별도 등록. 등록 후 재배포 필요
- `GEMINI_API_KEY` 에 `NEXT_PUBLIC_` 을 붙이면 브라우저 번들에 그대로 실린다
- **API 라우트는 반드시 세션을 확인한다.** 키를 숨기는 것과 접근을 막는 것은 별개 문제이며, 인증이 없으면 이 엔드포인트가 공개 Gemini 프록시가 된다

# 10. 검증된 기술 함정

| # | 함정 | 대응 |
|---|---|---|
| ① | **EXIF GPS를 믿을 수 없다.** iOS에서 사진 선택 시 위치 정보가 제거되는 경우가 많다 | 촬영 시점에 `navigator.geolocation`으로 별도 획득 |
| ② | **위치 콜백 안에서 카메라를 열면 iOS에서 안 열린다.** 사용자 제스처 자격이 끊긴다 | 위치 요청과 `input.click()`을 **같은 탭 이벤트 안에서 동시에** 실행 |
| ③ | 위치 권한 거부 시 서비스 성립 불가 | 권한 요청 전 설명 화면. 거부해도 저장은 가능 |
| ④ | 폰 사진 3~5MB를 그대로 업로드하면 느리고 비쌈 | 클라이언트에서 긴 변 1600px, WebP 변환 |
| ⑤ | 무드를 자유 생성하면 "고요/고요한/차분함"이 섞여 차트가 깨짐 | `responseSchema` enum + DB CHECK 이중 방어 |
| ⑥ | Gemini 모델명이 자주 종료됨 | 환경변수로 분리. 404 시 교체 |
| ⑦ | Storage 경로 규칙 위반 시 403 | `{user_id}/파일명` 고정 |

# 13. 구축 순서

위험한 것부터. 스플래시와 온보딩은 **맨 마지막**이다. 만들기 쉽고 눈에 띄어서 먼저 손대기 쉬운데, 그러다 저녁에 GPS가 안 되는 걸 발견하면 하루가 날아간다.

| 순서 | 작업 | 시간 |
|---|---|---|
| 1 | Supabase 세팅(SQL/버킷/RLS) + 빈 화면 Vercel 배포 | 1h |
| 2 | **촬영 + GPS 스파이크 → 실제 폰으로 검증** | 1.5h |
| 3 | Gemini 라우트 → 캡션 1건 성공 | 1h |
| 4 | 리사이즈 → Storage 업로드 → DB 저장 | 1.5h |
| 5 | 로그인 + RLS 연결 | 1h |
| 6 | 피드 + 상세 | 1.5h |
| 7 | 지도 | 1h |
| 8 | 대시보드 3종 | 1.5h |
| 9 | 스플래시 + 온보딩 + PWA 매니페스트 | 1h |

**2~3번이 오늘의 분기점.** 여기가 막히면 나머지를 만들 이유가 없고, 뚫리면 나머지는 검증된 기술이라 시간만 들이면 된다.
